## 二、根因定位（本轮两个用户可见问题）

### 1「动漫海报加载不出来」——不是图床拦截，是字段形态

frodo `/api/v2/tv/recommend` 的封面字段有两种形态：

- `cover_url`：字符串（部分条目才有）；
- `pic`：对象 `{large: ..., normal: ...}`。

旧代码 `j['pic']?.toString()` 会把对象变成 `{large: https://img3...}` 这种**伪地址**，
`Uri.parse` 直接抛 `FormatException: Scheme not starting with alphabetic character`。
受影响的是所有走 feed 的榜单——恰好是「日本动画 / 国漫 / 欧美动画」，
而「热门动漫」走 rexxar collection（字符串字段）一直正常，所以看起来像「只有动漫坏」。

实测（`tool/poster_probe.dart`）：修复前三个渠道 9 张封面全部 `ERR FormatException`，
修复后全部 `200`。

### 2「国漫资源过少」——单标签只有 3 条

`tags=国漫` 实测 3 条，`国产动画` 20 条，`中国动画` 2 条。旧实现只用 `国漫`，
一屏都凑不满。现改为 `multiTag` 三标签各自取 21 条后轮播交织去重（`show_service.dart:104-122`）。

## 四、误报与「部分成立」

1. **「`_load` 在 await 后才读 `_genre`/`_channel`，会把新类型数据写进旧缓存」——误报。**
   Dart 条件表达式的条件与实参都在 `await` 前**同步求值**：发出请求用的就是调用瞬间的
   `_genre`/`_channel`，与 `final d = _data;` 取到的缓存项是同一时刻的同一个 key。
   即便用户随后切换，回包也只写回它自己那条缓存（`home_page.dart:151-180`），不存在串写。
2. **「multiTag 的 `per` 是 `max(count, X)`，大 start 下会因接口上限漏条」——部分成立，已简化。**
   已改成 `per = count`：每个标签固定从头取一满页，交织结果的前缀天然稳定；
   国漫可用总量约 44 条（3 个标签去重后），继续翻页会返回空页并按「到底」处理，属预期。
3. **「`pickCoverUrl` 应优先 `pic.large` 而不是 `cover_url`」——不影响结果。**
   两种地址在显示前都会经过 `stablePosterCandidates` 归一成同一组 `p<id>` 稳定地址；
   且实测 `cover_url` 与 `pic.large` 指向同一张图。为降低改动面暂不调整优先级。
4. **「`imageCandidates` 是死代码」——保留。** 它是图床地址规整的公开纯函数，
   `test/image_test.dart` 与 `test/subtitle_test.dart` 依赖它做回归，非生产热点。

## 五、扩展性分析

**目标 A：新增「电影」大分类**

- 当前阻碍：`HotTab` 是枚举、`kChannels` 以它为 key；`fetchHot` 的 collection 分支与
  `detail()` 已按 `isTv` 分流，电影侧缺 `movie_hot` 等 collection 名与类型表。
- 最小改动：`HotTab` 加 `movie('电影')` → `kChannels` 加一组 collection（`movie_hot` 等）
  → `genresOf` 返回 `kMovieGenres`（标签用 `电影,战争` 前缀）→ `fetchByGenre` 不变。
- 改动面：3 个文件约 40 行，UI 零改动（首页 TabBar 自动多一个 Tab）。

**目标 B：地区 / 年份多维筛选**

- 当前阻碍：`Genre` 只承载单一 `tags` 串；三个页面的筛选状态是各自 `_genre` 单值，
  没有「facet 组合」抽象，加第二维要改 3 处状态机。
- 最小改动：把 `Genre` 升级为 `FilterFacet {label, tagFragment}`，页面状态改
  `Map<FacetKind, String>`，取数时把 fragment 用逗号拼成 `tags`（接口支持多值已实测）。
- 改动面：模型 + 3 个页面约 200 行；建议同时抽取 `ShowGridList(loader)` 收敛三份分页逻辑。

**目标 C：三处「筛选 + 分页」状态机合并**

- 当前阻碍：`home_page` / `search_page` / `genre_page` 各有一份 `_loading/_start/_hasMore/错误态`
  与「切换筛选要重置」的样板，新增第 4 个入口只能复制。
- 最小改动：抽 `PagedGridController`（纯 Dart，可单测）+ `PagedGridView`（只管渲染三态），
  三个页面只提供 `Future<List<ShowItem>> Function(int start)`。
- 改动面：新增 2 文件、三页面各减 60~80 行；风险集中在滚动控制器归属与
  `RefreshIndicator` 组合，建议单独一版做。
