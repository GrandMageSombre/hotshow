# 审查报告 14 — v1.12.0 高清渠道调研 + 多仓清单支持

## 一、调研做了什么

目标：找出能拿到**真正高清**片源的渠道，而不是靠站点标签猜。

1. 用公开检索收集了 TVBox / 影视仓生态的清单地址（`wuxierj/TVBox` 汇总页、
   影视仓配置合集等），共 20+ 条；
2. 在沙箱里逐条拉取：**只有 `kstore.vip` 能直连**（0.2s / 34KB），
   `cdn.jsdelivr.net`、`gh-proxy/ghfast/ghproxy`、`gitlab/jihulab`、中文域名站点
   全部 TLS 握手超时或 HTTP 错误；
3. 对能拿到的清单解析 maccms 接口并实测码率——`fish.json` 是**多仓/聚合型**配置，
   里面没有直接的 `provide/vod` 接口，所以这一轮**没能新增可测样本**。

已有实测数据（上一轮，仍然有效）：

| 站点 | 片名 | 码率 |
|------|------|------|
| bdzy | 赛博朋克：边缘行者 第1/5/10集 | 1273 / 1309 / 1308 kbps |
| bdzy | 流浪地球2 | 601 kbps |
| bfzy | 流浪地球2（标 HD） | 532 kbps |

**结论**：公开「4K 接口」多是采集站合集，标 4K ≠ 4K 文件；真正的 4K 高码率集中在
自有网盘 / Emby / Jellyfin 这类渠道，而它们**与 maccms 协议不兼容**，本 App 接不进来。
这条写进了 `docs/高清源渠道.md` 第四节，避免继续在采集站里空转。

## 二、因此本轮改的是「怎么把这些渠道接进来」

| 改动 | 说明 |
|------|------|
| **多仓清单支持** | `subCatalogUrls()` 解析 TVBox 的 `urls: [{name,url}]`，`fetchCatalog` 跟进一层（≤8 个子仓）。「无邪多仓」这类一个地址含多个子仓的配置现在能用了 |
| **配置文件过滤** | `.json` / `.txt` / `.js` 地址不再被当成采集接口（多仓的子仓地址、drpy 脚本源都会被剔掉） |
| **预设清单 chips** | `kPresetCatalogs`：摸鱼 / 王二小 / 无邪多仓 / 老刘备 / 分享 / 高天流云 / 潇洒 / 儿童专线，点一下直接拉取+探测 |
| **多行地址输入** | 清单输入框支持换行/逗号分隔，一次贴多条并合并去重 |
| **文档** | 新增 `docs/高清源渠道.md`：渠道表、在 App 里怎么用、接不进来的渠道、以及「多少 Mbps 算清晰」的参考值 |

## 三、自查发现的问题（已修）

| # | 问题 | 后果 | 处理 |
|---|------|------|------|
| 1 | 配置文件过滤放在 `_candidateFromUrl` 里，而 `_toMaccmsApi` 会先把 `https://a.com/sub.json` 补成 `https://a.com/sub.json/api.php/provide/vod` | 过滤对多仓子仓完全失效，子仓会被当站点探测，白跑一堆请求 | 把判断前移到 `_resolveApi`（补全之前），并在 `_candidateFromUrl` 里补 `.json/`、`.txt/`、`.js/` 的包含判断做双保险 |
| 2 | 多仓只跟进一层 | 深层嵌套的仓库拿不全 | 有意为之：再深容易滚雪球（8×8 个请求），文档里写明只有一层 |
| 3 | 预设 chips 容易被误解为「内置了资源站」 | 与「工程不写死站点」的原则冲突 | chip 上方加了一句说明：这些是配置地址，能不能用由 App 现场探测决定；`kPresetCatalogs` 的 dartdoc 也写明 |

## 四、遗留

- 预设清单会腐烂（域名/路径变化），且**本机网络无法验证**，只能靠用户端探测；
  `kPresetCatalogs` 是常量，后续可以考虑改成可远程更新的订阅。
- 「多仓」目前只跟进一层；如果某个仓库的子仓里还有 `urls`，那部分会被忽略（有意的上限）。
- 真正的 4K 渠道（网盘/Emby）需要另开协议支持，属于产品方向问题，不在本轮范围。
