# 审查报告 7 — v1.7.1（修复「搜索没反应」）

- 审查时间：2026-10-29
- 审查对象：搜索页状态机（`search_page.dart`）、`PagedShowList` 分页契约、`GenreBar` 点击语义
- 审查方式：4 视角并行，**A（架构/同类缺陷）、B（搜索链路）正常返回；C（生命周期）、D（测试体验）被模型限流（429）中断**，
  这两部分由主控自查补足（见第四节）
- 验证结果：`flutter analyze` 0 问题；`flutter test` **135/135**（新增 3 条回归）
- 结论：这是一次由 v1.5.0 重构引入的**显示层回归**（数据链路本身是好的）；审查还顺带挖出两个同源缺陷

## 一、根因

`_search()` 只做了 `_lastQuery = kw` 赋值，没有 `setState`。而搜索页 body 是：

```dart
browsing ? PagedShowGrid(_genreList!) : (_lastQuery.isEmpty ? 历史 : PagedShowGrid(_searchList))
```

- 不重建 → body 永远走「历史」分支；
- `PagedShowList` 的 `notifyListeners` 只驱动 `PagedShowGrid` 里的 `AnimatedBuilder`，
  而那个 widget 当时根本不在树里 —— 通知没有接收者。

所以请求发出去了、结果也回来了，就是没有任何 widget 去渲染它。**数据层无辜，纯 UI 状态没触发重建。**

## 二、已修复

| # | 问题 | 来源 | 修复 |
|---|------|------|------|
| 1 | `_search` 缺 `setState`，输入关键词界面无反应 | 用户反馈 | `setState` 内一次性更新 `_lastQuery/_genre/_genreList`，并在退出分类浏览时 dispose 旧列表 |
| 2 | 清空输入时同样只赋值不重建，无法回到历史页 | A | `_onChanged('')` 改 `setState` |
| 3 | **点「全部」标签回不到搜索历史**：`g.isAll` 分支调 `_exitGenre()`，而关键词模式下 `_genreList == null` 会直接 return，不重建 | A（严重） | `g.isAll` 分支自己 `setState`；并让 `GenreBar` 对「已选中」的 chip 也回调（原来 `if (g != selected)` 直接吞掉点击） |
| 4 | **搜索永远只显示 20 条**：`PagedShowList.pageSize` 默认 21，而豆瓣搜索 `count=20`，`hasMore = 20 >= 21` 恒 false → 从不翻页 | B（严重） | `PagedShowList(pageSize: 20)` 且 loader 显式传 `count: 20`，两边对齐 |
| 5 | `list.reset()` 在 `setState` 之前调用，首帧 notify 打给还没挂载的网格 | A（建议） | 搜索页/分类页统一「先 setState 挂载 → 再 reset」 |
| 6 | 输入时先退出分类浏览再等 600ms，中间会闪一下搜索历史 | 主控自查 | 不在 `_onChanged` 里提前退出，交给 `_search` 一次性切换 |

## 三、B 视角核对过、确认没问题的点

| 场景 | 结论 |
|------|------|
| 连续输入 `a` → `ab` | 旧 debounce 被 cancel；`_search` 读的是 `_controller.text`，不会把旧值写进 `_lastQuery` |
| 输入后立刻切分类浏览 | 两个 list 是不同实例，在途的搜索回包不会覆盖分类列表 |
| 清空输入 | `ShowService.search('')` 短路返回空列表，不发请求、不报错；build 走历史页 |
| 断网/5xx | 错误态可重试，重试时 `_lastQuery` 仍正确 |
| 点历史词 | `_controller.text = kw` 是程序赋值，不触发 `onChanged`，只会搜一次 |

## 四、C / D 视角（429 限流，主控自查）

**生命周期/并发**：

- `_search` 的 `setState` 都在 `await` 之前，await 之后不再碰 State，不会 after-dispose；
- 旧的 `_genreList` 先 `setState` 摘出树再 `dispose`，`AnimatedBuilder` 通过 `didUpdateWidget`
  自动退订，`removeListener` 在 dispose 后是安全空操作；
- `dispose()` 顺序（cancel timer → controller → focus → 两个 list）无问题；
- 搜索页常驻 `IndexedStack`，`initState` 只跑一次，`historyStore.load()` 不会重复。

**测试/体验**：

- 新增 3 条回归，均在修复前的代码上会失败：
  1. 输入关键词等 600ms → 必须出现结果卡片；
  2. 回车搜索 → 出结果且写入历史，清空 → 回到「搜索历史」并显示关键词；
  3. 搜索后点「全部」→ 必须回到搜索历史；
  另加一条单测：`pageSize=20` 且返回 20 条时必须 `hasMore=true`（防第 4 条复发）。
- 仍缺：搜索结果为空时的引导文案、搜索失败重试的显式按钮（`PagedShowGrid` 已有整页重试，但没测）、
  下拉刷新在搜索结果内的行为（可用但未测）。

## 五、暂缓项

1. **把历史/结果/空态分支下沉进 `PagedShowGrid`**（A 建议 2）：能彻底消除「切换瞬间无监听者」的脆弱点，
   但要改三个页面的调用方式，留待下次重构。
2. **页面状态收进 `ChangeNotifier`（如 SearchPageModel）**（A 建议 4）：根治「改字段忘 setState」，
   改动面大，建议和「列表/网格切换」一起做。
3. **`PagedShowGrid` 的整页重试/空态未加测试**：优先级次之。

## 六、下一步

1. 三端重新出包（APK / Windows / iOS IPA），在真机确认搜索能出结果、能翻页、能回历史。
2. 若还想更稳，下一版做「页面状态 Model 化」，把这类回归从「靠自觉」变成「架构上不可能」。
