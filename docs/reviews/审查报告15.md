# 审查报告 15 — v1.13.0 红果短剧 + 网址抓取

本轮新增两块能力，四视角（架构扩展性 / 领域正确性 / 线程与性能 / 代码质量与体验）并行审查。
下面每一条都**回读过源码核实**，子智能体的误判单独标注。

## 一、本轮做了什么

| 模块 | 文件 | 说明 |
|------|------|------|
| 红果短剧 | `lib/services/hongguo_service.dart`、`lib/pages/hongguo_page.dart` | 热播榜 + 真人剧/漫剧/AI 剧三个频道，分类可分页；详情页解析 `vid_list` 成逐集播放地址 |
| 网址抓取 | `lib/services/page_scraper.dart`、`lib/pages/web_grab_page.dart` | 三层策略：直链 → 爱看机器人专用解析 → 通用静态嗅探 |
| 入口 | `home_page.dart`（AppBar 剧院图标）、`search_page.dart`（搜索历史页两张横排卡） | |
| 自检工具 | `tool/hongguo_check.dart` | `dart run` 直连站点，验证榜单/详情/分类分页与抓取 |
| 播放页 | `player_page.dart` | 红果/抓取源换源后无法搜回，菜单里加显式切回入口 |

**红果网页版只有 360p**（`720p/480p/1080p` 实测全部 404），与 App 内一致，
页面顶部已写明，避免用户以为是播放器没切清晰度。

## 二、修复清单

### P0（阻断，全部已修）

| # | 文件 | 问题 | 处理 |
|---|------|------|------|
| 1 | `page_scraper.dart` `calcToken` | `rest.substring(off + 8)` 只判了 `off`，没判 `off+8` → **`RangeError` 直接崩**（D 实测跑测试就崩，是真 bug 不是理论问题） | 按 JS `substring` 语义把 end 夹到长度上限 |
| 2 | `page_scraper.dart` 3.1/3.2 正则 | 普通字符串 `'…\\ssrc…'` 里的 `\s` 是**字面 s**，实际正则变成「排除字母 s」→ 含 `s` 的地址被截断（实测 `?from=timeline&isappinstalled=0` → `…&i`） | 全部改 raw 字符串 `r'''…'''` |

| 4 | `GrabResult.toResource` | `vodId: pageUrl.hashCode` —— Dart 的 `String.hashCode` **不保证跨进程一致**，重启后进度/离线缓存/字幕偏移全部对不上 | 直接用 `pageUrl`（本身稳定且唯一） |

| 6 | `hongguo_page._loadMore` | 无 epoch 保护：切分类时旧请求后到会覆盖新列表，且 `_loading` 卡 true | 加 `_epoch` 计数，回包代次不符即丢弃 |
| 7 | `hongguo_page._loadMore` | 一次失败就 `_hasMore = false`，**永久无法再翻页** | 失败只记 `_error`，不清 `_hasMore`，列表底部给「加载失败，点这里重试」 |

| 10 | `calcToken` 语义 | 旧实现 `break` 让 token 静默截短 → 接口 403 | 改 `continue` + 夹断，与 JS `substring` 一致 |
| 11 | `web_grab_page._ResultCard` | 0 条结果仍显示**绿色对勾「解析完成」** | 改 `search_off` 图标 + 「没找到视频地址」+ 错误色 |

## 三、误报澄清

| 子智能体结论 | 核实结果 |
|------|------|
| B：把 ikanbot 做成内置专用解析 = 「变成盗版入口，必须移除」 | **不采纳**。项目自 v1.7.0 起的定位是「内置的只有元数据接口和播放器，片源由使用者自行提供」；本轮加的是**用户自己粘贴网址后的解析**，没有内置任何站点目录、没做全站自动遍历、没有保存地址。与既有「用户自填采集接口」是同一性质。真正的区别只在于这一步不需要「采集接口」这个前置知识。已在 README 免责声明里补一条明确边界。 |
| A：`_SourceSheet` 会把红果源换掉且不可逆 | 部分成立：确实搜不回，但用户是**主动点「换片源」**才发生的，不是自动替换。已通过 P1-6 加显式切回入口解决。 |
| D：浅色/深色主题下新增页面有硬编码颜色 | 不成立。两个新页面全部走 `Theme.of(context).colorScheme`，无硬编码色值。 |
| D：`_HongguoTile` / `_ResultCard` 触摸目标不足 48dp | 不成立。卡片本体即点击区域（整块 tile），远大于 48dp；内部按钮用 Material 默认最小尺寸。 |
| C：`_loadMore` 的 `_loading` 卡 true | 成立且已修（P0-6/7）。 |

## 四、扩展性分析

**目标能力：从「写死几个站点」演进到「任意站点都能试一把」。**

现状阻碍：

1. `PageScraper.grab()` 里是 `if (ikanbot.handles(pageUrl))` 硬分支——加第三个站点要改这个方法；
2. 每个专用站点都是一段独立代码，没有统一接口；
3. 静态嗅探只能看首屏 HTML，覆盖不了 JS 渲染。

**最小改动路径**（不改变现有行为、只抽一层）：

```dart
abstract class SiteParser {
  bool handles(Uri url);
  Future<GrabResult> parse(HttpClient http, Uri url);
}
// PageScraper 持 List<SiteParser>，grab() 里 firstWhere 命中即用
```

改动面：`page_scraper.dart` 一个文件（`IkanbotParser` 加 `implements SiteParser`），
`grab()` 里的 `if` 换成遍历。约 20 行，不影响测试。

**不做的事**：不做 WebView 嗅探 / MITM 抓包。前者要引入 webview 依赖并处理证书与播放器桥接，
后者在 Android 上要求用户安装 CA 证书，安全代价远超收益。这条已经写进类文档注释。

- 通用嗅探对 JS 渲染站点无效，页面已如实提示；

- 三部串行请求的最坏耗时较长，弱网下体验偏慢（P2）。
