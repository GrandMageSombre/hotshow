# 审查报告 6 — v1.7.0（全平台「使用声明」）

- 审查时间：2026-10-29
- 审查对象：`widgets/legal_notice.dart`、启动时序、`LICENSE`、README/版本说明、各平台版权字段
- 审查方式：4 个子智能体并行（法务合规 / 交互与可测试性 / 生命周期与持久化 / 平台覆盖）
- 验证结果：`flutter analyze` 0 问题；`flutter test` **131/131 通过**
- 结论：文案与实现均按「个人自用、禁止商业」收敛，法务与生命周期各抓到 2 处会真正出问题的点，
  已全部修复；「每版本弹一次」的判断也在审查中被确认合理

## 一、四个视角的核心结论

| 视角 | 严重 | 建议 |
|------|------|------|
| 法务合规 | LICENSE 允许修改/再分发与「个人自用」矛盾；弹窗称「不存储视频」与离线缓存功能矛盾 | 单方格式条款效力存疑（民法典 496 条）、缺侵权联系方式与适用法律、豆瓣接口条款未提 |
| 交互/可测试性 | 手动「i」与自动弹窗可能叠两层 | 宽度写死 420、try/catch 过宽、缺小屏/返回键/读屏测试、语义碎片化 |
| 生命周期/持久化 | 无崩溃级 | 会话内无去重、写失败会「永久弹」、版本号双源 |
| 平台覆盖 | 版本号双源、宽度写死 | 每版本弹一次合理；Windows `Runner.rc` 版权仍是模板；macOS 多窗口各弹一次可接受 |

## 三、误报与暂缓

1. **「应该每次启动都弹」——不采纳。** 用户诉求是「所有版本都要有说明」，按版本弹一次 + 首页常驻「i」已满足；
   每次启动弹对个人自用场景是骚扰。若以后要改，只需把 `_seenKey` 的比较改成总弹（一行）。
2. **「macOS/Windows 多开两个实例会各弹一次」——接受。** 跨进程去重需要文件锁，代价远大于收益。
3. **「抽 `legal_store.dart` 与既有 store 风格对齐」——暂缓。** 只有一个 key，抽 store 收益低；
   当前读/写已各自 try，行为可控。
4. **「用 `--dart-define` 注入版本号」——暂缓。** 已用测试兜住双源问题；引入构建参数会让
   `flutter run` / CI / 本地构建三处都要带参，反而增加出错面。
5. **「iOS 显示名旁没有声明」——不成立。** 首次启动弹窗已覆盖；App Store 场景也不存在（本项目不上架）。

## 四、覆盖度核对（四平台）

| 产物 | 说明文案 | 版权字段 |
|------|----------|----------|
| Android APK | 启动弹窗（首启/换版本） | `android:label=热剧速览` |

| iOS 未签名 IPA | 启动弹窗 | `CFBundleDisplayName=热剧速览`，版权随 Info.plist |
