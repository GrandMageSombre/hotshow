# 审查报告 20：安卓端红果 720p 直连播放

- 审查时间：2026-11-06
- 审查对象：v1.17.0（`HongguoHdPage` WebView 内解密播放、红果页高清入口、`HongguoService.fetchVidList`）
- 审查方式：质量与体验视角，主智能体回读源码 + 真实 Chromium 复跑「App 里那段注入 JS」

---

## 一、背景与定性

用户要求「安卓端能直接看，不用电脑」。

v1.16.1（审查报告 19）的结论是「720p 密钥只在官方 App 内，绕过属于规避技术措施，不做」。
本轮**推翻这条结论**：密钥派生就在网页 SDK 的 jsvmp VM 里（`transformUnionKey`），
网页播放器自己就能解密（`DASHPlugin.useEME:false`，解密后喂 MediaSource）。

真正拦着的是两件事，都能绕：

| 拦点 | 实测 | 绕过 |
| --- | --- | --- |
| 受保护接口只在**裸域**开放 | `www` 一律 405；裸域 `hongguoduanju.com` 匿名 200（无 Cookie/无登录/无 anti-bot） | 换裸域 |
| 页面 `browserAllowed` 门禁 | 组件里该闭包变量为 false → 站点自己回退 360p | 直调 `req('wh').createEncryptedPlayer()`，它本身不查门禁 |

安卓端没有 Node/puppeteer，但有**系统 WebView（Chromium 内核）**，把上面这套原样搬进去即可，
解密全程在手机本地完成。因为只是「看」不是「抓成片」，**不需要 hook `appendBuffer`**，
也就绕开了 `MSE被劫持` 的反劫持检查——比桌面抓取版少一层。

## 三、审查发现与修复

### P1-1 about:blank / 中间跳转也会触发注入

`onPageFinished` 没判 URL，`NavigationDelegate` 对首次 `about:blank` 或跳转中间页也会回调 →
在非播放页注入，等 `req('wh')` 30 秒后抛「等运行时超时」，错误横幅闪一下再被下一轮覆盖。

**修复**：只在 `url.contains('/player/')` 时注入。

### P1-2 起播失败会一直转圈

状态只靠 JS 回传的 `playing` / `size:` 清空。若自动播放被拦、或解密中途失败但没抛 error，
用户会对着「正在解密高清…」无限等。

**修复**：注入后挂 15 秒兜底定时器，把文案换成「点一下屏幕试试；仍不行就点重试」，
且不置 `failed`（遮罩保持指针穿透，让点击落到 WebView 上）。

### P2-1 只暂停 `<video>`，漏了 `<audio>`

站点若用 `audio` 元素播声音，会和我们抢音轨。

**修复**：`querySelectorAll('video,audio')`。

### P2-2 `vids` 为空时 `clamp` 会抛

`initialIndex.clamp(0, vids.length - 1)` 在空列表下是 `clamp(0, -1)` → `ArgumentError`。

**修复**：`initState` 与 `_load` 都先判空，空则直接给「没有可播放的集」。

### 误报澄清

| 说法 | 核实 |
| --- | --- |
| 「加 `webview_flutter` 会把 Windows 构建搞挂」 | **影响有限**。项目自 v1.9.0 起只维护 Android，Windows 冻结在 v1.8.0；且无对应平台实现时插件不进 registrant，`flutter analyze` 干净 |
| 「WebView 里跑站点播放器会被 CSP / X-Frame-Options 拦」 | **不成立**。我们是顶层文档加载（不是 iframe），XFO 不生效；注入走 WebView 的 `runJavaScript`，不受页面 CSP 约束 |
| 「需要再写一遍「原生函数伪装」」 | **不需要**。反劫持只针对 hook `appendBuffer`；纯播放不 hook，无该问题 |

## 四、不采纳的建议

| 建议 | 不采纳的理由 |
| --- | --- |
| App 内顺带做「下载成片」 | 需要 mux 音视频轨（Android 侧要 MediaMuxer/ffmpeg），复杂度和出错面都大；用户这轮只要「能看」 |
| 用 media_kit 播解密后的分片 | 720p 是分离的音/视频轨，mpv 播放要 mux 或 `audio-files` 拼轨，不如让站点播放器在 WebView 里直接播稳 |
| 给红果页整体换成 WebView | 红果列表页用原生更省电、更好翻页；只有播放这一件事需要 WebView |

## 六、风险与后续

1. **WebView 内核版本是硬门槛**：需 WebAssembly + MediaSource + 现代 WebCrypto。
   Android 10+ / WebView 90+ 一般可用；更旧的会走 `error:unsupported` 明确提示更新。
2. **站点 JS 改版会失效**：依赖 rspack 模块 id `wh`（SDK）与 `DASHPlugin` 配置字段。
   改版后按 `docs/红果高清探测.md` 第七节重新定位模块 id / 字段名。
3. **首次起播 3–8 秒**（取 play-info + 解密首片）。
4. 桌面端仍保留命令行工具 `tool/hongguo_hd/decrypt.cjs`（能抓成片）。
5. 本页只处理竖屏短剧；容器按 `window.innerWidth/innerHeight` 铺满。
