# 审查报告 21：红果高清改原生播放（隐藏 WebView 解密 + 本地缓存）

- 审查时间：2026-11-07
- 审查对象：v1.18.0（`HongguoHdFetcher` 隐藏 WebView 解密、`HongguoMux` 纯 Dart 合并、`HongguoHdPage` 改调度页）
- 审查方式：质量与体验视角，主智能体回读源码 + 真机问题复现思路核对

---

## 一、问题定性（用户反馈）

v1.17.0 把站点播放器直接放在**可见** WebView 里播，用户实测两个问题：

| 反馈 | 根因 |
| --- | --- |
| 失败率很高 | 可见 WebView 里站点自己的播放器与注入的播放器抢生命周期；站点会重渲染/跳转，`onPageFinished` 反复触发；解密要 3–8 秒，期间站点 UI 会先弹出 |
| 解出来又跳回红果页面 | 站点在 WebView 内部做了路由跳转（播放页/登录/App 深链兜底），用户看到的是站点页面而不是自家播放器 |

结论：**「可见 WebView 当播放器」这条路本身就不该走**。WebView 只适合当「解密机」，
播放必须交给项目自己的 `PlayerPage`（media_kit/libmpv），才能和采集站片源体验一致。

## 三、关键设计

1. **WebView 只当解密机**：`SizedBox(2×2)` + `IgnorePointer` 压在角落，用户全程看不到网页。
2. **确定性收流**：`window.__hgArm` 在 `createEncryptedPlayer` 之前置位，只认此后创建的
   **第一条视频轨 + 第一条音频轨**（`__hgTaken` 各只取一次），避免把站点自带播放器的
   分片混进来 —— 这是上一版「分片污染」的根因。
3. **纯 Dart 合并**：不引入 ffmpeg（移动端体积/授权都麻烦）。两条 fMP4 的
   视频轨 `track_ID=1`、音频轨 `track_ID=2`（实测），合并时把 `tkhd/trex/tfhd` 的
   track_ID 归一化，再按 `tfdt` 解码时间交错 `moof+mdat`；`mvhd.next_track_ID` 改成 3。
   实测 27MB+2.9MB 合并耗时 **17ms**，产物 ffprobe 认作 720×1280 H.264 + AAC 02:54。
4. **本地缓存**：`{support}/hongguo_hd/{series}_{vid}_720p.mp4`，重看/切集回来直接秒开，
   也不再需要 WebView 参与。缓存命中的判断是「文件存在且 >100KB」。
5. **失败可重试**：超时 150 秒、`error` 消息、`unsupported`（老 WebView）分别给明确文案。

## 四、审查发现与修复

| 级别 | 问题 | 修复 |
| --- | --- | --- |
| P1 | `onPageFinished` 在站点跳转时会反复触发，重复注入 | 只认 URL 含 `/player/`，且每页只注入一次；JS 侧再加 `__hgHd2` 幂等锁 |
| P1 | 站点自带播放器的分片会混进捕获流 | `__hgArm` + `__hgTaken` 只取自己那两条轨 |
| P1 | 合并后 track_ID 冲突（两轨都叫 1） | `_remapTrackId` 递归改 `tkhd/trex/tfhd`，并断言单测 |
| P2 | 进度条长时间不动（只在 `sizes` 后更新） | 按已收字节 / 期望字节算，2% 一档刷新 |
| P2 | 解密失败时临时文件残留 | `_cleanup()` 删临时目录；`dispose()` 也清 |
| P2 | 上一集没解完又点下一集 | `_job != null` 直接拒绝并提示「上一集还在解密」 |
| P2 | 页面 `File` 类型没导入 | 补 `dart:io show File, Platform` |

### 误报澄清

| 说法 | 核实 |
| --- | --- |
| 「纯 Dart 合并会掉帧」 | **不成立**。只搬 box、不碰编码数据；单测 + ffprobe 双验，时长/流数与源一致 |
| 「2×2 的 WebView 解不出视频」 | **不成立**。MSE 解码与显示尺寸无关；`videoWidth` 仍是 720 |
| 「file:// 会被 PlayerPage 补 Referer 搞坏」 | **不成立**。`_headersFor` 只在 `uri.hasAuthority` 时才补 Referer，`file://` 没有 authority |

## 六、风险与后续

1. **首集解密耗时**：取 play-info + 解密整集，几十秒量级（Qt 4 倍速拉流）。已做缓存，后续秒开。
2. **磁盘占用**：每集约 30MB，缓存在应用支持目录；暂未做自动清理，后续可加「清缓存」。
3. **站点改版**仍会影响（模块 id `wh`、config 字段），按 `docs/红果高清探测.md` 第七节重新定位。
4. **选集**目前是「解一集播一集」，不做整剧预解（102 集 × 30MB 不现实）。
