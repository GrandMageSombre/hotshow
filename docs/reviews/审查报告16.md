## 二、误报澄清（子智能体结论经实测不成立）

| 结论来源 | 子智能体的说法 | 实测结果 | 处理 |
| --- | --- | --- | --- |
| B 领域 | 「`Uri.parse` 对中文会抛 FormatException，必须 `encodeFull`」 | **误报**。`Uri.tryParse('https://a.com/中文【4K】.m3u8')` 正常返回，自动转成 `%E4%B8%AD%E6%96%87...`；空格也自动变 `%20` | 反而证明 `encodeFull` 是多余的（见 P1-2） |
| B 领域 | 「属性值里有未转义引号会让整条频道丢失」 | **部分误报**。实测没丢，仍是 1 条，但名字被切错成「他说」 | 归入 P0-1 一并解决 |
| B 领域 | 「BOM 头会导致首行解析异常」 | **误报**。`\uFEFF#EXTM3U` 被 `startsWith('#')` 吃掉，实测解析正常 | 不修 |
| C 并发 | 「`_loadAll` 全失败会显示空列表而不是错误」 | **误报**（C 自己在同段末也纠正了）。`load()` 里有 `if (result.isEmpty) throw`，会正常报错 | 不修 |
| C 并发 | 「页面 dispose 不取消在途请求 = 资源泄漏」 | **不成立**。`mounted` 守卫已防 setState 崩溃，只是浪费一次网络 | 不修 |
| A 架构 | 「直播频道包装成 MediaResource 会污染历史记录」 | **本轮已提前处理**。A 只读了 `media_resource.dart`，没读到 `player_page.dart` 新增的 `isLive`；`_saveProgress()` 首行已 `if (widget.isLive) return;` | 已落地，无需再改 |

## 三、本轮发现与修复

### P0（实测可复现，已修）

**P0-1 台名里的逗号被截断**
`lib/models/iptv_channel.dart` · `_parseExtInf`

原实现取「最后一个引号外逗号」当属性区/显示名的分界。实测：

```
#EXTINF:-1 group-title="央视",CCTV-1, 综合   →  name = 综合      （应为 CCTV-1, 综合）
#EXTINF:-1 tvg-name="A, B",C, D             →  name = D         （应为 C, D）
```

台名带逗号不算罕见（「CCTV-1, 综合」这种写法），截断后台名错、搜索也搜不到。

**修复**：改取**第一个**引号外逗号 —— 属性值全在引号内，第一个引号外逗号必然是属性区结束处。
新增 2 条回归用例钉死这两种输入。

### P1（真实缺陷，已修）

**P1-2 `Uri.encodeFull` 把已有的 `%XX` 二次编码**
`lib/services/iptv_service.dart` · `_uriOf`

实测 `Uri.encodeFull('https://a.com/a%20b.m3u8')` → `https://a.com/a%2520b.m3u8`。
现有 6 个源恰好都不含 `%`，所以没炸；但任何带转义字符的源都会 404。

**修复**：直接 `Uri.tryParse`（它自己就会转非 ASCII 和空格），删掉 `encodeFull`。

**P1-3 频道列表可能是 GBK，会被解成乱码**
`lib/services/iptv_service.dart` · `_decode`

原实现 UTF-8 解失败只做 `allowMalformed`，结果是满屏 `�`，台名全废、搜索全失效。
现有 6 个源恰好都是 UTF-8，属于「今天没炸」的隐患。

**修复**：UTF-8 严格解 → GBK → `allowMalformed` 三级降级，复用项目已有依赖 `charset`。

**P1-4 切源失败会把当前列表清空**
`lib/pages/live_page.dart` · `_load`

`_load` 一开始就 `_playlist = null`。新源拉取失败时只剩错误页，用户既丢了原列表、又停在错误的源上，只能自己点回去。

**修复**：进入 `_load` 时存下 `prevSource / prevPlaylist / prevGroup`，失败分支整套回退。

**P1-5 空态文案在「没搜索」时也劝人「换个关键词」**
`lib/pages/live_page.dart` · `_emptyMessage`

原来只有「关键词空且未开高清」才给准确文案，其余统一提示「试试换个关键词或关掉只看高清」。
切到 `bestfan_province`（188 条全无 HD 标记）开「只看高清」→ 关键词明明是空的，却被建议换关键词。

**修复**：按「有关键词 / 只看高清 / 源本身是空」三种情况分别给话。

**P1-6 「95%」会被读成「95% 一定能播」**
`lib/pages/live_page.dart` · `_sourceChip`

`channels · health%` 里的 health 是**抽样 40 个频道**估出来的可播率。
UI 上写「1298 · 5%」既容易被当成「保证值」，也把 `IptvSourceDef.note` 里「死链多」这种关键提醒彻底埋掉了。

**修复**：标签改成 `1298台 · ~5%`（波浪号表示估计值），note 挂到 `Tooltip` 上，长按可见。

**P1-7 每敲一个字全量重算三遍过滤**
`lib/pages/live_page.dart` · `_visible`

`_visible` 是 getter，每次 build 都跑 分组 → 高清 → 关键词 三道 O(n)，还反复 `toLowerCase`。
合并模式 2700 条，输入框里每敲一个字都重建。

**修复**：加签名缓存（`identityHashCode(_playlist)|_group|_hdOnly|_keyword`），条件不变直接返回上次结果。

**P1-8 一个镜像卡住要等 20 秒**
`lib/services/iptv_service.dart` · `_fetchWithMirrors`

`_fetch` 内部两个 20 秒超时，三个镜像串行 = 单源最坏 60 秒，合并六个源时用户要对着转圈等一分多钟。

**修复**：每个镜像外层加 12 秒总限时（加速前缀实测 0.6–1.5 秒，12 秒已经很宽松）。

### P2（体验/性能，已顺手修）

| 项 | 位置 | 处理 |
| --- | --- | --- |
| 台标按原图解码 | `live_page.dart` · `_channelTile` | `cacheWidth: 84`（显示尺寸 42×32 的 2 倍） |
| 每次进 App 都回到第一个源 | `live_page.dart` · `initState` | 记住上次选的源（`SharedPreferences`），失效则回默认 |

### P3（记录，暂不处理）

- `IptvService` 的 `_cache` 无淘汰，键只有 7 个（6 源 + 合并），有界，可接受。
- `_sourceBar` / `_groupBar` 每次 build 重建；分组条最多几十个 Chip，实测无感知。
- `_kLiveSiteId` 定义在 `live_page.dart` 末尾（被前面的 `_play` 用到）。Dart 允许，但与 `hongguo_service.dart` 的 `siteId` 放在 service 里的风格不一致，后续统一时再挪。
- 频道名去重粒度：合并模式按 `name` 去重（`CCTV1` / `CCTV1 HD` 算两个台）。这是刻意的——不同清晰度确实是不同流，合成一条反而丢信息。

## 四、扩展性分析

### 目标一：用户自定义 m3u 源（最关键的一条）

| 项 | 内容 |
| --- | --- |
| **阻碍** | `kIptvSources` 是 `const`，`sourceOf()` 只查这张表；`load()` 遇到非内置 id 直接抛「未知的直播源」。自定义源在入口就被拒。 |
| **最小改动** | 1) 加 `IptvSourceStore`（照搬 `source_store.dart` 的 `ChangeNotifier + SharedPreferences` 写法）；2) 把 `kIptvSources` 降级为「内置预设」，改为 `store.sources = 内置 + 用户添加`；3) `load()` 改成接收 `IptvSourceDef` 而不是 id；4) 源条末尾加「＋ 添加源」。 |
| **改动面** | `iptv_service.dart` 的 `sourceOf` / `load` / `_loadAll`；`live_page.dart` 的 `_sourceBar`；新增一个 store 文件。约 200 行，不动解析层。 |

### 目标二：收藏频道 / 最近看过

| 项 | 内容 |
| --- | --- |
| **阻碍** | 频道没有稳定 id（`name` 会改、`url` 会变），也没地方存。 |
| **最小改动** | 新增 `IptvFavoriteStore`，用 `name + url` 作为键；`live_page` 列表项加星标，顶部源条右边加「收藏」筛选。 |
| **改动面** | 新 store + `live_page` 两处 UI，不动 service。 |

### 目标三：EPG 节目单

| 项 | 内容 |
| --- | --- |
| **阻碍** | `#EXTM3U x-tvg-url="…"` 这个属性目前解析完就丢了，没有 XMLTV 解析器。 |
| **最小改动** | `parseIptvPlaylist` 顺手返回 `xTvgUrl`；新增 `xmltv.dart` 解析 `<programme>`；频道详情页按 `tvg-id` 匹配。 |
| **改动面** | model 的返回值要改（`IptvPlaylist` 加字段，调用处 2 处）+ 新解析器 + 新 UI。中等工作量。 |

## 五、建议的下一步优先级

1. **先真机验一遍能不能播**（最高优先级）。本轮所有验证都停在「m3u8 地址能拉回来」，libmpv 在 Android 上实际解码还没跑过。重点看：直播流进度条显示、切台是否残留旧画面、硬解兼容性。
2. 自定义 m3u 源（扩展性硬阻塞，改动面小）
3. 收藏频道（个人自用最实用的一条）
4. 源可用性自检（把「抽样 40 个」变成用户可主动触发的全量检测，参考 `bitrate_probe.dart` 的「点了才跑、先提示耗流量」范式）
