### macOS 平台

| 项 | 处理 | 原因 |
|----|------|------|
| `flutter create --platforms=macos` | 生成 `macos/` 工程（Flutter 3.47 用 Swift Package Manager，无 Podfile） | — |
| `DebugProfile/Release.entitlements` | 加 `com.apple.security.network.client` | App Sandbox 默认禁止出网，缺了所有接口/海报都会失败 |
| `Info.plist` | `NSAllowsArbitraryLoads=true`、`CFBundleDisplayName=热剧速览` | 采集站多为 http 明文；程序坞显示中文名 |
| `AppInfo.xcconfig` | `PRODUCT_NAME=HotShow` | 可执行文件名保持 ASCII |
| `MainFlutterWindow.swift` | 初始 1100×760、最小 900×640、居中 | 手机宽度开局只剩两列海报 |
| `analysis_options.yaml` | excludes 加 `macos/**` | 避免扫描 Xcode 生成物 |

> **未在本机验证**：Windows 无法运行 Xcode 工具链，macOS 构建需在 Mac 上执行
> `flutter build macos --release`。已按 Flutter 官方模板 + 沙箱要求静态核对；
> 首次在 Mac 上构建若报插件/最低系统版本问题，优先看 `MACOSX_DEPLOYMENT_TARGET`（模板 10.14）。

## 三、误报与暂缓

1. **「`FilterSelection` 与 `Genre` 职责重叠」——成立，已修（#4）。** 修完 `Genre` 只描述
   「类型」这一个维度，`FilterSelection` 负责组合三维，职责不再交叉。
2. **「首页 `_cache` 与 `PagedShowList` 双重管理生命周期，可能重复 dispose」——误报。**
   `_list` 由 `_listFor()` 创建时即写入 `_cache`，页面 dispose 只遍历 `_cache` 一次；
   `_trimCache` 先 `remove` 再 `dispose`，不会二次释放。
3. **「AnimatedBuilder 监听的 list 被 trim 后报错」——误报。** `AnimatedBuilder.didUpdateWidget`
   会先把旧 listenable 的 listener 摘掉，`ChangeNotifier.removeListener` 在 dispose 后是安全的空操作。
4. **「`NotificationListener` 每帧触发 loadMore 会与 RefreshIndicator 抢手势」——误报。**
   `loadMore` 内部有 `_loading` 守卫，回调返回 `false` 不拦截冒泡。
5. **「年份表缺老片入口」——部分成立，已扩到近 12 年。** 豆瓣年份是普通 tag（`1994` 有效），
   再往前把 `buildYears(span:)` 调大即可；不额外加「更早」是因为它会退化成「不筛年份」，
   与「全部」重复，容易误导。
6. **「`PagedShowGrid` 每次 notify 重建整个 GridView」——可接受，暂不改。**
   `GridView.builder` 只构建可见项（约 20~30 个），当前数据规模下无感；
   真要优化可把 `itemBuilder` 提到顶层或只让尾部 tail 订阅。

## 四、扩展性分析（下一层）

**目标 A：再加「综艺」大分类**

- 现状：需要补 `HotTab.variety`、`kChannels[variety]`、`kVarietyGenres`、
  `kEndpointByScope[GenreScope.variety]`、`scopeOf` 分支 —— 共 5 处，其中 2 处由编译器强制（穷举 switch / Map 缺 key）。
- 阻碍：`genresForScope` 与 `scopeOf` 是两份 switch，新增域要同步改；可以合并成
  `Map<GenreScope, List<Genre>>` 一张表，减少一处。
- 改动面：约 30 行，UI 零改动。

**目标 B：列表/网格视图切换**

- 现状：`PagedShowGrid` 已留 `itemBuilder`，只需在页面加一个 `viewMode` 状态并传不同的 `itemBuilder`；
  网格 delegate 需要支持 `SliverList`，可给 `PagedShowGrid` 加 `listMode` 分支。
- 改动面：组件 40 行 + 一个设置项（`shared_preferences`）。

**目标 C：筛选条件持久化 / 分享**

- 现状：`FilterSelection.key` 已经是稳定字符串（`genre|area|year`），可直接存
  `shared_preferences` 或写进 URL query；恢复时按 key 反解需要一张 label→tag 映射表。
- 改动面：新增 `services/filter_store.dart` 约 60 行，三个页面各接一行。

**目标 D：macOS 发布链路**

- 阻碍：无 Apple 开发者证书 → 只能本地自签运行；公证（notarization）需要 `notarytool` + 账号。
- 最小路径：GitHub Actions 的 `macos-latest` runner 上 `flutter build macos --release`
  产出 `.app`/`.dmg`，签名可选；至少能保证「有人在 Mac 上构建过一次」。

## 五、下一步优先级

1. 在 Mac 上跑一次 `flutter build macos --release`，确认插件（media_kit / path_provider /
   url_launcher / shared_preferences）都能编译，再决定是否补 `Podfile` 兜底。
2. 把 `scopeOf` 与 `genresForScope` 合成一张表（目标 A 的前置，改动小）。
3. 筛选条件持久化（目标 C），对「上次看到哪」体验提升明显。
4. 列表/网格切换（目标 B）可等用户反馈再做。
