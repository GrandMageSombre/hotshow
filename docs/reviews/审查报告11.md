# 审查报告 11 — v1.10.0「清晰度」入口重做（跨站点换片源）

## 一、问题定位（先查证，再改代码）

用户反馈：播放《赛博朋克：边缘行者》时**看不到清晰度切换**。

实测（`tool/quality_diag.dart` + 直接打接口）：

| 检查项 | 结果 |
|--------|------|
| 站点 `api.apibdzy.com` 搜「赛博朋克」 | 1 条：《赛博朋克：边缘行者第二季》，**1 条线路**，线路名 `dbm3u8` |
| 该集 m3u8（91,487 字节） | `#EXTM3U` + `#EXT-X-TARGETDURATION` + 分片列表，**没有 `#EXT-X-STREAM-INF`** → 单码率媒体列表 |
| 站点 `bfzyapi.com` | 有资源，线路名 `bfzym3u8`，同样不含清晰度信息 |
| 线路名含 4K/1080/蓝光/高清 | 无 |

结论：**不是探测失败，是采集站根本不给多码率**。所以 v1.8.0 的「按母带分档」和 v1.9.0 的「按线路名猜清晰度」在这类片源上都不会产生任何选项，
`_qualityOptions` 为空 → 按钮直接隐藏 → 用户看到的就是「没有清晰度可选」。

能真正换清晰度的唯一现实路径：**同一部剧在别的站点往往是另一个版本**（不同站采集的源不同，分辨率/码率不同）。

## 二、本轮改动

1. **清晰度按钮常显**（不再依赖有没有分档），点开即可看到：
   - 当前档位 + `当前实测 1920×1080`（mpv 解码输出尺寸，只作副信息）；
   - 母带分档（源真是多码率时才有）；
   - 名字带清晰度字样的其它线路（有才显示）；
   - **换片源（其它站点）**；
   - **切回上一个片源**（换过才有）；
   - 什么都没有时给一句说明：「这个片源只有单码率……试试换片源」。
2. **换片源面板 `_SourceSheet`**：按片名重搜所有已启用站点，两轮关键词（原片名 + `normalizeTitle` 归一化名，
   解决「赛博朋克：边缘行者第二季」与「赛博朋克边缘行者」两种写法），合并去重后 `rankResources` 排序（带年份），
   列表标注 `站点 · N 线路 · M 集 · 更新状态`，当前源标「（当前）」。
3. **换源是原地替换**：新增 `_resource` 字段（`_r` 指向它），换源后复用同一个 `Player` 实例，
   保持当前集与播放位置（>2 秒才带位置），并把旧源压进 `_history` 支持一键切回。
4. 顺带：实测分辨率显示在底部信息栏（`站点 · 线路 · N 集 · 实测 1080P`）。

## 三、审查发现（四视角，本轮 A/B 两路返回，C/D 由主控自查覆盖）

### P1（已修）

| # | 位置 | 问题 | 后果 | 处理 |
|---|------|------|------|------|
| 1 | `_switchResource`（原 pushReplacement） | 换源重建整个 `PlayerPage` → 销毁 `Player` 重新初始化 | 换源瞬间黑屏重连，且上一个源被丢弃 | 改成原地替换 `_resource` + `_openCurrent()`，并加 `_history` 支持切回 |
| 2 | `_qualityLabel` | 曾把 mpv 实测分辨率当按钮主标签 | 720p 被解码成 1080 输出时会显示「1080P」，冒充标称档位误导人 | 按钮只显示标称档位/「清晰度」；实测值降级为菜单与底栏的副信息（带「实测」字样） |
| 3 | `_openCurrent` ep==null 分支 | 提前 return 时没清 `_pendingSeek` | 换源到「没有剧集的线路」后，下次打开会跳到上一条片源的位置 | 该分支里一并清空 |
| 4 | `_switchResource` 字幕 | 无条件把 `_subtitleMode` 置 `off` | 用户原本看内嵌字幕，换源后字幕直接没了 | 保留模式，只在原本是 `off` 且有外挂字幕时切到 `external` |
| 5 | `_videoW/_videoH` | 换源/换集不重置 | 新源首帧前仍显示上一源的「实测 1920×1080」，同尺寸时流不重发会一直是旧值 | 换源、换集时置 null |

### P2（未做）

- `_SourceSheet` 与 `resource_page.dart` 的「搜索 + 排序 + 站点结果聚合」逻辑重复（排序规则要改得改两处），
  后续可抽公共搜索组件。
- `PlayerPage` 的 `_isDesktop` 与桌面控件分支在「只维护 Android」后已成死代码，可择机清理。
- 换源面板最多列 40 条、两轮搜索串行；站点多时等待偏长（可并发两轮）。

### 误报澄清

- 「两轮搜索会 cancel 掉正在跑的订阅」——核实**不成立**：`onDone` 时上一轮订阅已结束，
  新一轮订阅在 `_runRound` 内部才创建，cancel 的是已完成的旧订阅。
- 「换源后标题/缓存 key 新旧混用」——核实**不成立**：页面内全部走 `_r`；
  `_EpisodeSheet` 里的 `widget.resource` 指的是该组件自己的 `resource: _r` 参数。
- 「`_history` 与 `qualityStore` 的 key 会错位」——核实**不成立**：两者都用 `_r.key`，换源后同步更新。

## 四、扩展性分析

| 目标能力 | 当前阻碍 | 最小改动路径 | 改动面 |
|----------|----------|--------------|--------|
| 换源时自动挑「更清晰」的站点 | 换源前无法知道目标站点分辨率（单码率、无语义标签） | 记录「实测分辨率」到本地，按站点维度累计；换源列表按历史实测排序 | 中（需要持久化 + 采样） |
| 换源不打断播放 | 换源仍需 `open` 新地址（libmpv 单实例） | 双 Player 预加载目标源首帧，切过去再销毁旧的 | 大（内存 ×2，且 media_kit 多实例需验证） |
| 站点级搜索复用 | 播放页与资源页各写一套 | 抽 `ResourceSearchController`（流式结果 + 排序），两处共用 | 中 |
| 多码率源支持 | 采集站基本不给 master | 保留现有 `optionsFromPlaylist` 逻辑即可，无需改动 | 无 |
