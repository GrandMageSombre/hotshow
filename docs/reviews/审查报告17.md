## 二、误报澄清

| 来源 | 说法 | 核实结果 |
| --- | --- | --- |
| B 领域 | 「`Media(httpHeaders:)` 只对主 m3u8 生效，分片请求不带 UA 会 403」 | **不成立**。media_kit 的 `httpHeaders` 最终落到 mpv 的 `http-header-fields`，是**整个 demuxer 级别**的全局头，主列表、变体、分片共用同一套。B 在报告末尾也自行更正 |
| B 领域 | 「UA 里有括号+逗号会切错台名」 | **不成立**。UA 全程在引号内，`_firstUnquotedComma` 的引号态保护生效。已补用例钉死 |
| C 并发 | 「groupOverride 重建 477 个对象会卡顿」 | **不成立**。只拷 7 个 String 引用，实测 <1ms |
| C 并发 | 「`_sourceBar` 的 fold 每次 build 求和」 | **不成立**。7 个 int 相加，微秒级 |

## 三、本轮发现与修复

### P1（已修）

**P1-1 `http-referer`（单个 r）不被识别**
`lib/models/iptv_channel.dart` · `_parseExtInf`

`http-referrer`（双 r）是 iptv-org 的写法，但 VLC 系和不少国内源写的是 `http-referer`（单 r）。
原来只认双 r，这类源的 Referer 会丢，CDN 判盗链直接 403。

**修复**：`http-referrer` / `http-referer` / `referer` 三种拼法都认；`#EXTVLCOPT` 分支从
`endsWith('referrer')` 改成 `contains('referer')`（同时命中两种拼法）。

**P1-2 三个正则 getter 每次调用都重新编译**
`lib/models/iptv_channel.dart` · `isHd` / `is4K` / `playable`

原实现把 `RegExp(...)` 写在 getter 里。列表里每个 tile 调 3 次，一屏 15 个约 45 次；
开「只看高清」时 `_computeVisible` 对 3200 条逐条 `isHd` —— 一次过滤就是 3200 次正则编译。

**修复**：提成 `static final`，只编译一次。

**P1-3 源标签上看不出「这里有 NBA」**
`lib/pages/live_page.dart` · `_sourceChip`

用户提的就是「例如 NBA」，但 chip 上只有篮球图标 + `477台 · ~80%`，
`note` 里那句「NBA TV / ESPN / Sky Sports」只有长按 Tooltip 才看得到 —— 移动端没人会去长按。

**修复**：`IptvSourceDef` 加 `badge` 字段，体育源标成红色 `NBA` 角标，直接挂在名字后面。

### P2（已修）

| 项 | 位置 | 处理 |
| --- | --- | --- |
| `channels` / `health` 是 `required`，自定义源没法填 | `iptv_service.dart` | 改成可选（默认 0），`statsText` 在 0 时不显示「0台 · ~0%」 |
| `groupOverride` 手写 `IptvChannel(...)` 重建，模型加字段会静默丢 | `iptv_service.dart` · `_loadOne` | 改 `IptvChannel.withGroup()`，集中在一处拷字段 |
| `isSports` 误判「体育彩票」、漏判英超/斯诺克/F1 | `iptv_channel.dart` | 排除「彩票」，关键词扩到联赛与项目名 |
| note 写「CCTV 体育系列」不准确（实际只有 5 个台） | `iptv_service.dart` | 改成逐个列出：5+ / 16 / 台球 / 高尔夫网球 / 风云足球 |
| `_fetchWithMirrors` 重复判断 `startsWith('http')`，`isAbsolute` 成了摆设 | `iptv_service.dart` | 直接收 `IptvSourceDef`，用 `def.isAbsolute` |

### P3（已修，低风险）

**P3-6 过滤缓存签名用 `identityHashCode`**
`live_page.dart` · `_visibleKey`

对象被回收后新对象可能复用同一个 identityHashCode，理论上会命中过期缓存。
目前有 `_visibleKey = ''` 兜着，但改成自增版本号更稳（也不贵）。

## 四、未采纳的建议

| 建议 | 不采纳的理由 |
| --- | --- |
| 按联赛派生子分组（NBA / 英超 / 西甲…） | 只能靠频道名猜，`Arena Sport 1` 这种根本猜不出转播什么。猜错比不分组更糟。搜「NBA」已经能精确命中 |
| 体育频道名中文化 | 477 个台名翻译量太大且会过期（频道改名/换台），现有英文名 + 台标已经够认 |
| 抽 `PlayHeaders` 值类型统一点播/直播两套 header | 两边各自 5 行，抽出去反而多一层间接；等真有第三个使用方再说 |
| 支持无引号的 UA 值 | M3U 语法里带空格的属性值必须加引号，不加就是非法格式；`[^\s]*` 截断是符合语法的行为 |
| 绝对 URL 也走加速代理 | 实测 `gh-proxy.com` 不代理 `iptv-org.github.io`（404），没有可用镜像 |

### 目标：用户自定义源（报告 16 遗留）

本轮把 `channels`/`health` 改成可选，`statsText` 也做了 0 值处理 —— 自定义源接入时
不会再显示「0台 · ~0%」。剩下的是：`kIptvSources` 仍是 `const`、`sourceOf()` 只查它。
照报告 16 的路径做 `IptvSourceStore` 即可，本轮没有引入新的阻碍。

### 目标：EPG 节目单

仍是报告 16 说的那条：`#EXTM3U x-tvg-url` 解析完就丢，没有 XMLTV 解析器。
体育源尤其需要节目单（「现在在播哪场」），但这是独立工作量。
