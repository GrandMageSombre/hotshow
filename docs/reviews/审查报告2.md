## 三、误报与「部分成立」

1. **「没有 open 互斥，可能出现画面在 A 集、UI 显示 B 集」——部分成立。**
   media_kit 的 `open()` 内部走同一个命令队列（stop → loadlist），后一次 open 一定最后执行；
   epoch 只负责丢弃旧流程的后置动作。已补 `ep == null` 分支自增 epoch，避免早退时旧 finally 改状态。
2. **「`CacheWidth` 在无界宽度对 inf 取整」——成立但不是真机路径**（网格/详情都是定宽）。
   仍加了 `isFinite` 保护，降低以后复用到横向列表时踩坑的概率。
3. **「GBK 阈值 0.12 对短字幕偏严」——部分成立。** 单纯下调阈值会让西文误判率上升，
   改为「常见汉字命中 ≥3 或汉字占比 ≥0.12」双条件（`subtitle_text.dart:90`），
   并补了「含时间码稀释」的 GBK 单测。Big5 仍不支持（无纯 Dart 码表），已在报告 1 / README 说明。

## 五、扩展性分析（更新）

**结论：报告 1 的路径仍然成立，且本轮已把两个前提条件补上。**

1. **再接一个中文字幕源**：把 `SubtitleCandidate.legacyId/fileId` 收进 `extras`、`freeDownloadable` 变成字段，
   再抽 `abstract class SubtitleSource { id, name, search(), download() }` + 按 `candidate.source` 路由。
   改动面：`models/subtitle.dart`、`services/subtitle/`（新增源文件）、`subtitle_service.dart`、`subtitle_page.dart`。
2. **本地字幕文件**：`file_picker` + `importFromFile(path)` 复用 `_saveArchive`（解包/转码/落盘/记住选中都已具备）。
3. **字幕字号/描边**：与 `sub-delay` 同一条 `NativePlayer.command` 路径（`sub-font-size` / `sub-border-size`），
   偏好存 `SubtitleStore`，`_applySubtitle` 时下发。
4. **按 IMDb 精确匹配**：豆瓣无 IMDb id，需手填或接 TMDB；`open_subtitles.dart` 加 `imdb_id` 参数即可。
5. **双语/第二字幕轨**：mpv 同时只显示一条 `sid`，需 `secondary-sid` 或先合并两份字幕。
