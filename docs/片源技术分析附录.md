## 2. MP4 直链与 HTTP Range 协议（实测）

视频直链服务的核心是 **HTTP Range 请求**：播放器的"拖动进度条/随机访问/多线程分段下载"全部依赖它。

### 2.1 请求与响应实测

```bash
# 只取前 1KB 探测服务端是否支持分段
curl -s -r 0-1023 -D - -o /dev/null \
  "https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.mp4"
```

实测响应（摘录，MDN 的视频实际托管在 Google Cloud Storage 上）：

```http
HTTP/1.1 206 Partial Content
Accept-Ranges: bytes
Content-Range: bytes 0-1023/1128375
Content-Length: 1024
Content-Type: video/mp4
x-goog-stored-content-length: 1128375
x-goog-hash: md5=orlvrrAlgXcKRzb2G9O2tw==
Server: UploadServer
```

**分析要点（可直接写进报告）：**
- `206 Partial Content` + `Content-Range: bytes start-end/total` 是分段访问的标准应答；
- `Accept-Ranges: bytes` 由服务端声明支持范围请求；不支持时返回 `200`（整文件）；
- 4 分段并发下载一个 1.1MB 文件 ≈ 用 4 个 Range 请求（0-25%、25-50%…），播放器 seek 就是"发起一个从目标字节开始的 Range 请求"；
- `x-goog-hash: md5=...` 这类响应头可以用于完整性校验。

### 2.2 各源 Range 支持实测结果

| 来源 | HEAD | Range(0-1KB) | 结论 |
|------|------|--------------|------|
| MDN flower.mp4 | 200 | **206** | 支持随机访问 ✅ |
| W3Schools mov_bbb.mp4 | 200 | **206** | ✅ |
| test-videos.co.uk BBB | 200 | **206** | ✅ |
| Video.js oceans.mp4 | 200 | **206** | ✅ |
| 豆瓣预告片 mp4 | 200 | **206** | ✅ |

## 3. HLS 自适应码率流（Apple 官方示例实测）

Apple 为开发者提供的公开 HLS 示例流是国内**可直接连通**的最佳协议分析样本：

```text
master（主清单）：https://devstreaming-cdn.apple.com/videos/streaming/examples/img_bipbop_adv_example_ts/master.m3u8
```

### 3.1 主清单（master.m3u8）实测摘录

```m3u8
#EXTM3U
#EXT-X-VERSION:6
#EXT-X-INDEPENDENT-SEGMENTS

#EXT-X-STREAM-INF:AVERAGE-BANDWIDTH=8144656,BANDWIDTH=8178040,
CODECS="avc1.64002a,mp4a.40.2",RESOLUTION=1920x1080,FRAME-RATE=60.000,
CLOSED-CAPTIONS="cc1",AUDIO="aud1",SUBTITLES="sub1"
v9/prog_index.m3u8

#EXT-X-STREAM-INF:AVERAGE-BANDWIDTH=3240596,...,RESOLUTION=1280x720,...
v6/prog_index.m3u8
#EXT-X-STREAM-INF:AVERAGE-BANDWIDTH=1292926,...,RESOLUTION=768x432,...
v4/prog_index.m3u8
```

**码率阶梯（实测整理）：**

| 分辨率 | 帧率 | 平均码率 | 视频编码 | 音频编码 |
|--------|------|----------|----------|----------|
| 1920x1080 | 60fps | ~8.14 Mbps | H.264 (avc1.64002a) | AAC-LC (mp4a.40.2) |
| 1280x720 | 60fps | ~3.24 Mbps | H.264 | AAC-LC |
| 960x540 | 60fps | ~2.22 Mbps | H.264 | AAC-LC |
| 768x432 | 30fps | ~1.29 Mbps | H.264 | AAC-LC |

### 3.2 媒体级清单（v5/prog_index.m3u8）实测摘录

```m3u8
#EXTM3U
#EXT-X-TARGETDURATION:6
#EXT-X-VERSION:3
#EXT-X-MEDIA-SEQUENCE:0
#EXT-X-PLAYLIST-TYPE:VOD
#EXTINF:6.00000,
#EXT-X-BITRATE:2060
...（共 100 个 6 秒 TS 分片，VOD 点播型清单）
```

**分析要点：**
- 主清单只描述"有哪些档位"，媒体清单才是真实分片表；播放器先取 master → 按带宽选档 → 播放中动态切档（ABR）；
- `CODECS="avc1...,mp4a..."` 让播放器在**下载任何分片之前**就能判断本机是否支持该编码；
- `#EXT-X-PLAYLIST-TYPE:VOD` 表示清单不会变化（点播）；直播则是 EVENT/LIVE，清单滚动更新；
- 同样的分片思想在 DASH 中对应 `.mpd` 清单（可提一句作对比）。

## 4. 豆瓣预告片接口（官方宣传物料，实测最快 ~3MB/s）

本项目（`lib/services/`）已在使用的豆瓣 App 接口可额外拉取**官方预告片**，这是正版的宣传物料，可作为"在线观看"功能的合法演示内容。

### 4.1 接口实测

```text
GET https://frodo.douban.com/api/v2/tv/{subject_id}/trailers   （电视剧）
GET https://frodo.douban.com/api/v2/movie/{subject_id}/trailers （电影）
（附 apiKey/_ts/_sig 签名参数，签名算法见 lib/services/api_client.dart）
```

实测返回结构（`trailers[]` 数组，摘自《漫长的季节》subject 35588177）：

```json
{
  "id": "303732",
  "title": "花絮：制作特辑 (中文字幕)",
  "subject_title": "漫长的季节",
  "cover_url": "https://img3.doubanio.com/img/trailer/medium/2891085207.jpg",
  "video_url": "https://vt1.doubanio.com/202610241630/bd11ebc9.../view/movie/M/403030732.mp4",
  "runtime": "08:53",
  "file_size": 124397588,
  "create_time": "2023-04-24"
}
```

### 4.2 签名时效直链分析（防盗链样本）

`video_url` 路径中的 `202610241630` 段是**时间戳签名**（观察：当日有效，次日失效），配合路径中的哈希构成时效性防盗链：

- 客户端**不能长期缓存播放地址**，必须在播放前实时调接口换取新 URL；
- 这是国内主流平台防盗链的通用形态（签名 URL + Referer/UA 校验 + CDN 节点分发）；
- 实测该直链无需 Cookie/Referer 即可 `206` 分段访问，网速 ~3MB/s（国内节点，晚高峰亦应流畅）。

> 合规性说明：预告片是版权方主动分发的宣传物料，接口为豆瓣官方 App 同款，仅用于技术演示/元数据展示，不属于正片传播。

## 5. Internet Archive：公有领域片源平台的接口范本（需国际网络）

[archive.org](https://archive.org) 收录大量**公有领域电影**（1920-1950 年代老电影为主），其 Items API 是研究"开放片源平台该如何设计"的最佳范本。⚠️ 大陆直连超时，本节接口结构基于其公开文档与多年稳定形态整理，**建议挂梯子后按下述命令逐条实测后再引用**。

### 5.1 三类端点

```text
元数据   GET https://archive.org/metadata/{identifier}
文件直链 GET https://archive.org/download/{identifier}/{filename}   （302 → iaNNNN.us.archive.org 节点）
网页播放 https://archive.org/embed/{identifier}                     （官方 iframe 嵌入器）
搜索     GET https://archive.org/advancedsearch.php?q=...&output=json
```

### 5.2 metadata 响应结构（关键字段）

```json
{
  "metadata": { "title": "...", "date": "1968", "rights": null, "collection": ["feature_films"] },
  "files": [
    { "name": "Night.Of.The.Living.Dead_512kb.mp4", "format": "h.264", "size": "410938749", "length": "96:30" },
    { "name": "night_of_the_living_dead.gif", "format": "Animated GIF" }
  ],
  "server": "ia801604.us.archive.org",   // 该条目所在存储节点
  "dir": "/29/items/night_of_the_living_dead",
  "d1": "ia601604.us.archive.org",       // 灾备节点
}
```

直链拼接规则：`https://archive.org/download/{identifier}/{files[].name}`，服务端 302 到 `{server}/{dir}/{filename}`。

### 5.3 搜索示例（公有领域电影检索）

```bash
curl "https://archive.org/advancedsearch.php?q=collection%3A%28feature_films%29+AND+date%3A%5B1920-01-01+TO+1949-12-31%5D&fl%5B%5D=identifier&fl%5B%5D=title&fl%5B%5D=year&sort%5B%5D=downloads+desc&rows=20&page=1&output=json"
```

**注意：** IA 不对每个条目做版权审查，"老电影 ≠ 一定公版"。报告引用具体条目前，应核对条目的 rights 字段及外部公版数据库。

## 6. 苹果CMS VOD 资源站协议（公开规范·仅作协议对比）

苹果CMS（AppleCMS V10）是国内广泛使用的一套开源影视建站系统，其配套的"资源站"生态对外暴露统一的 VOD JSON 接口。**本节仅描述该公开协议格式用于报告中的设计对比，不指向任何具体站点——对接未授权资源站分发正片属侵犯信息网络传播权，请勿实际使用。**

### 6.1 协议形态（公开规范）

```text
目录（分页）  GET /api.php/provide/vod/?ac=list&t={分类ID}&pg={页码}
详情（含播放）GET /api.php/provide/vod/?ac=detail&ids={vod_id}
```

- `ac=list` 返回 `page/pagecount/total` 与简略 `list[]`（vod_id/vod_name/vod_pic/class）；
- `ac=detail` 返回完整字段与 **`vod_play_url`**，集数编码格式为：

```text
第01集$https://cdn.example.com/xxx/01.m3u8#第02集$https://cdn.example.com/xxx/02.m3u8
（集名$地址 用 # 串联多集；常见为 m3u8 或 mp4 明文直链）
```

### 6.2 与正规平台的协议对比（报告核心论点素材）

| 维度 | AppleCMS VOD 资源站 | 豆瓣预告片接口 | Apple HLS 示例 | Internet Archive |
|------|--------------------|----------------|----------------|------------------|
| 内容授权 | ❌ 未授权正片 | ✅ 官方宣传物料 | ✅ 官方测试流 | ✅ 公有领域为主（逐条核对） |
| 鉴权 | 无 | HMAC-SHA1 签名（key+_ts+_sig） | 无（公开示例） | 无（公开API+限速） |
| 防盗链 | ❌ 明文直链 | ✅ 时效签名 URL（当日有效） | ❌（无需） | ❌（无需） |
| 频控/配额 | 无 | 有（匿名限速） | 有（CDN 层） | 有 |
| 地址时效 | 长期不变 | 短时效 | 长期 | 长期（节点会漂移） |
| 合规风险 | **高（侵权+挂马）** | 低（展示官方物料） | 无 | 低 |

**可写进报告的论点：** 资源站协议之所以"好用"，恰恰因为它放弃了鉴权、防盗链与频控——这三样是正规平台的合规成本；对采集链的治理（剑网行动历次通报）也正是围绕这三点展开的。

## 7. 报告写作建议

**可以放心引用/复现的：**
1. 本附录全部实测数据（curl 命令原样可复现，注明测试日期与网络环境即可）；
2. HLS/Range 协议分析（RFC 8216、HTTP Range RFC 7233 是公开标准）；
3. 苹果CMS 协议格式的**规范描述**（作为"行业协议对比"）；
4. IA API 文档与其收录的公有领域影片清单（核对版权后引用）；
5. 执法与行业数据：国家版权局"剑网行动"通报、CNNIC《中国网络视听发展研究报告》。

**不要做的：**
- 附任何具体采集站域名/接口地址；
- 引用采集站返回的正片数据作为"片源样本"（内容本身侵权）；
- 把签名破解、接口绕过写成教程（技术细节可以分析，绕过手段不要提供）。
