# 高清片源渠道调研（2026-10-31）

> 目的：搞清楚「哪里能拿到真正清晰的片源」，以及在**本 App（只吃 maccms `provide/vod` + 直链 m3u8）**
> 里哪些渠道能用、怎么用。
>
> 先给结论，再给可复制的地址清单。

## 一、结论先说

1. **采集站的「高清/4K」标签基本不可信。** 实测（下载真实分片算码率）：
   - `bfzy` 标着 **HD** 的《流浪地球2》只有 **532 kbps**；
   - `bdzy`《赛博朋克：边缘行者》第 1/5/10 集稳定在 **1.27–1.31 Mbps**；
   - 这类 maccms 采集源普遍 **0.5–1.5 Mbps**，属于「能看但不清」。
2. **同一部剧在不同站点码率可能差 2–3 倍**，所以「找高清」的实际操作是**多源横向实测**，
   而不是找某个「传说中的 4K 站」。App 的「换片源 → 测清晰度」就是干这个的。
3. **真正的高码率（1080p 4–8 Mbps、4K 15 Mbps+）几乎只存在于**：
   - 自己的网盘 / 自建 Emby、Jellyfin（合法，但**本 App 接不进来**，见第四节）；
   - IPTV 直播源（1080i/4K 频道，只覆盖直播，不是点播）。
4. 公开的「4K 接口」配置大多只是**采集站的合集**，标 4K 不等于给 4K 文件。

## 三、在 App 里怎么用

1. **一键试预设**：站点设置 → 自动搜索采集站 → 里面有一排胶囊按钮
   （摸鱼 / 王二小 / 无邪多仓 / 老刘备 / 分享 / 高天流云 / 潇洒 / 儿童专线），点一下就开始拉取+探测。
2. **一次贴多个地址**：输入框支持换行/逗号分隔的多条清单，会依次拉取并合并去重。
3. **多仓也能用**：配置里 `urls: [...]` 的子仓会被自动跟进一层（最多 8 个），
   把子仓里的采集接口一起收进来。
4. **验证清晰度**：进播放页 → 清晰度 → 换片源（其它站点）→ **测清晰度**，
   谁的 `≈x Mbps` 高就选谁；底部还会显示播放器实测分辨率（如 `实测 1920×1080`）。

## 四、本 App 接不进来的「真 4K」渠道（要说清楚）

| 渠道 | 能拿到什么 | 为什么接不进来 |
|------|------------|----------------|
| AList / OpenList 挂自己的网盘 | 自己文件的原码率（4K 原盘都行） | 它给的是 WebDAV/直链，不是 maccms `provide/vod`；本 App 的资源模型只认后者 |
| 自建 / 公益 Emby、Jellyfin | 高码率原盘 | 同上，协议不兼容（Emby 有自己的 API） |
| 阿里云盘 / 夸克 / 115 的分享 | 原码率 | 需要各自的客户端协议与登录态 |
| IPTV 直播源（公开 m3u 汇总） | 1080i / 部分 4K 频道 | 是直播，不是点播剧集；App 目前没有直播模块 |

要真正看 4K 原盘，现实做法是用支持这些协议的播放器（VidHub / Fileball / Emby 客户端 / 自己搭的
Jellyfin），本 App 的定位是「找剧 + 快速看采集站」。

## 五、怎么判断「真的清晰」

| 指标 | 参考值 |
|------|--------|
| 低 | < 1.2 Mbps（≈480p 水准，压缩痕迹明显） |
| 一般 | 1.2–2 Mbps（≈720p） |
| 较清晰 | 2–4 Mbps（≈1080p 中低码率） |
| 高清 | 4–8 Mbps（1080p 高码率） |
| 4K | 15 Mbps 以上 |

注意：码率不等于分辨率——同码率下 1080p 也可能比 720p 更糊（编码器/片源质量差异）。
App 里的 `实测 1920×1080` 是**播放器解码出来的真实尺寸**，可以和码率互相印证。
